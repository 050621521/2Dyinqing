## 1. 文档目标

本文件定义角色和单位的底层规则。

角色和单位系统需要支持 PVE、联机 PVE、人机 PVP、联机 PVP。

## 2. 单位定义

单位是地图和战斗中的可交互对象。

单位可以是：

| 单位类型 | 说明 |
|---|---|
| 玩家角色 | 玩家控制的角色 |
| 敌人 | PVE 中系统控制的敌对单位 |
| Boss | PVE 中高级敌人 |
| 友方 | 与玩家同阵营单位 |
| 对手角色 | PVP 中其他玩家控制的角色 |
| 召唤物 | 后续可能加入的临时单位 |

## 3. 单位基础字段

```json
{
  "id": "unit_001",
  "name": "流浪剑士",
  "unit_type": "player",
  "team_id": "team_1",
  "controller_type": "player",
  "max_hp": 50,
  "current_hp": 50,
  "energy": 0,
  "max_energy": 5,
  "deck_id": "deck_swordsman_001"
}
```

敌人、Boss、召唤物等非玩家单位也可以拥有 energy、max_energy 和 deck_id。

## 4. 控制类型

| 控制类型 | 说明 |
|---|---|
| player | 玩家控制 |
| ai | AI 控制 |
| remote_player | 联机玩家控制 |

PVE 中：

- 玩家角色 controller_type = player
- 敌人 controller_type = ai

PVP 中：

- 本地玩家 controller_type = player
- 对手玩家 controller_type = remote_player

人机 PVP 中：

- 玩家 controller_type = player
- 对手 controller_type = ai

## 5. 阵营规则

所有单位必须属于某个阵营。

示例：

```json
{
  "team_id": "team_1"
}
```

交互目标通过阵营判断：

- 敌人 = 不同阵营单位
- 友方 = 相同阵营单位
- 自身 = 释放者自己

## 6. 角色规则

角色是可被玩家选择或控制的单位模板。

角色包含：

| 字段   | 说明           |
| ---- | ------------ |
| 角色编号 | 唯一 ID        |
| 名称   | 显示名称         |
| 最大生命 | 生命上限         |
| 初始能量 | 战斗开始能量       |
| 最大能量 | 能量上限         |
| 初始卡组 | 初始拥有的卡牌和卡牌等级 |
| 可用模式 | PVE、PVP 或全部  |

## 7. 角色数据结构

```json
{
  "id": "hero_swordsman",
  "name": "流浪剑士",
  "available_modes": [
    "PVE",
    "PVP"
  ],
  "max_hp": 50,
  "initial_energy": 0,
  "max_energy": 5,
  "starter_deck": [
    {
      "card_id": "card_attack_001",
      "level": 1
    },
    {
      "card_id": "card_attack_001",
      "level": 1
    },
    {
      "card_id": "card_defense_001",
      "level": 1
    }
  ]
}
```

## 8. PVE 角色规则

PVE 中角色可以有：

- PVE 初始卡组
- PVE 成长路线
- PVE 奖励卡池
- PVE 专用数值

## 9. PVP 角色规则

PVP 中角色需要单独平衡：

- PVP 初始卡组
- PVP 禁用卡牌
- PVP 专用生命值
- PVP 专用能量规则
- PVP 专用技能数值

## 10. 底层不应该写死的内容

角色和单位系统不要写死：

- 玩家永远只有一个
- 敌人一定是怪物
- AI 单位一定是敌人
- 玩家单位一定属于 team_1
- 角色只能用于 PVE
- 角色数值只有一套

## 11. 第一阶段实现范围

第一阶段只实现：

- 1 个玩家角色
- 3 个普通敌人
- 1 个 Boss
- 玩家控制
- AI 控制
- 阵营判断
- 生命值
- 能量值
- 带等级的初始卡组
