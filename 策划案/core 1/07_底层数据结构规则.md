## 1. 文档目标

本文件定义项目底层数据结构规则。

本文件用于约束：

- 配置表如何拆分
- ID 如何命名和引用
- 卡牌、角色、敌人、地图如何表达
- 后续 Godot 导入工具如何读取数据
- 后续数据校验需要检查哪些内容

本文件只写数据结构规则，不写具体卡牌、角色、敌人和地图数值。

## 2. 数据分层

项目数据分为三层：

| 层级 | 目录 | 说明 |
|---|---|---|
| 规则文档 | `docs/` | 描述系统规则和字段含义 |
| 配置源数据 | `config/` | Obsidian 中编辑的配置表和记录 |
| Godot 运行数据 | `data/` | Godot 运行时读取的 JSON 数据 |

规则：

- 规则文档不维护大量具体数值
- 配置源数据负责具体卡牌、角色、敌人、地图和卡组
- Godot 运行时读取 `res://data/*.json`，而不是直接读取规则文档

## 3. 配置目录结构

```text
config/
├── tables/
└── records/
```

其中：

- `config/tables/` 保存 Obsidian Bases 表视图
- `config/records/` 保存表格中的具体记录

`.base` 文件负责显示和编辑表格。

`records` 中的记录负责保存实际配置数据。

## 5. 通用字段规则

### 5.1 ID

所有可引用对象必须有唯一 ID。

建议命名：

| 类型 | 示例 |
|---|---|
| 玩家卡牌 | `card_slash_001` |
| 敌人卡牌 | `enemy_card_bump_001` |
| 角色 | `hero_swordsman` |
| 敌人 | `enemy_slime` |
| Boss | `boss_forest_guardian` |
| 关卡地图 | `level_map_001` |
| 战斗地图 | `battle_map_001` |
| 关卡敌人实例 | `level_enemy_001` |

规则：

- ID 使用小写英文、数字和下划线
- ID 不使用中文
- ID 不使用空格
- ID 一旦被其他配置引用，不应随意修改

### 5.2 状态

配置可以使用 `status` 字段。

| 状态 | 说明 |
|---|---|
| `draft` | 草稿 |
| `ready` | 可用于第一版 |
| `disabled` | 暂不启用 |
| `deprecated` | 废弃 |

Godot 运行数据默认只包含 `status = ready` 的配置。

### 5.3 字段表写法

所有数据结构表必须使用数据字典格式。

字段表至少包含：

| 列 | 说明 |
|---|---|
| 中文字段 | 给策划和文档阅读使用的中文名称 |
| 英文字段 | 配置 frontmatter 和 Godot JSON 中实际使用的字段名 |
| 说明 | 字段含义、用途和引用关系 |
| 类型或取值 | 字段类型、枚举范围或引用对象 |
| 示例 | 典型填写值 |

规则：

- 配置文件和 Godot 运行数据只使用英文字段。
- 中文字段只用于文档和表格阅读，不进入程序读取逻辑。
- `id` 表示程序唯一标识，不是显示名称。
- `name` 表示界面显示名称，可以是中文。
- 引用字段必须说明引用哪张表的哪个字段。

## 6. 卡牌数据结构

卡牌主表记录卡牌不随等级变化的字段。

| 中文字段 | 英文字段 | 说明 | 类型或取值 | 示例 |
|---|---|---|---|---|
| 卡牌 ID | `id` | 卡牌的程序唯一标识，被卡组、等级表和运行数据引用。不是界面显示名。 | 小写英文、数字、下划线 | `card_slash_001` |
| 卡牌名称 | `name` | 玩家在界面上看到的卡牌名称。可以是中文。 | 文本 | `斩击` |
| 所属方 | `owner` | 标记卡牌属于玩家侧还是敌人侧，用于组卡和过滤。 | `player`、`enemy` | `player` |
| 卡牌类型 | `card_type` | 卡牌基础分类，用于 UI、筛选和部分规则判断。 | `attack`、`skill`、`status` | `attack` |
| 稀有度 | `rarity` | 卡牌品质，用于奖励池、卡框表现和后续平衡。 | `common`、`rare`、`precious` | `common` |
| 默认等级 | `default_level` | 新获得该卡牌时使用的默认等级。 | 正整数 | `1` |
| 最大等级 | `max_level` | 该卡牌允许升级到的最高等级。 | 正整数 | `3` |
| 释放类型 | `release_type` | 玩家或 AI 使用卡牌时的释放方式。 | `target`、`area`、`self` | `target` |
| 范围形状 | `shape` | 范围型卡牌的命中形状。非范围卡可填 `none`。 | `none`、`circle`、`square`、`rect`、`fan` | `none` |
| 目标类型 | `target` | 卡牌允许作用的目标阵营或对象。`enemy` 表示相对于卡牌使用者的敌对阵营单位，不是 `enemies` 表中的敌人类型。 | `enemy`、`ally`、`self` | `enemy` |
| 效果类型 | `effect` | 卡牌结算时触发的核心效果。具体数值在等级表中配置。 | `damage`、`heal`、`shield`、`gain_energy` 等 | `damage` |
| 配置状态 | `status` | 控制该卡牌是否进入 Godot 运行数据。 | `draft`、`ready`、`disabled`、`deprecated` | `ready` |

卡牌等级表记录随等级变化的字段。

| 中文字段 | 英文字段 | 说明 | 类型或取值 | 示例 |
|---|---|---|---|---|
| 卡牌 ID | `card_id` | 引用卡牌主表中的 `cards.id`，表示这条等级数值属于哪张卡。 | 已存在的卡牌 ID | `card_slash_001` |
| 模式 | `mode` | 指定该等级数值用于哪个玩法模式。PVE 和 PVP 数值可以分离。 | `pve`、`pvp` | `pve` |
| 等级 | `level` | 当前数值对应的卡牌等级。不能超过该卡的 `max_level`。 | 正整数 | `1` |
| 能量消耗 | `energy_cost` | 使用该等级卡牌需要消耗的能量。 | 非负整数 | `1` |
| 效果数值 | `effect_value` | 与 `effect` 配合使用的核心数值，例如伤害、治疗、护盾或获得能量。 | 整数 | `8` |
| 冷却回合 | `cooldown` | 使用后需要等待的回合数。第一版可以为空或 0。 | 非负整数或空 | `0` |
| 备注 | `note` | 给设计和调试使用的说明，不参与战斗结算。 | 文本或空 | `基础伤害` |

## 9. Boss 阶段数据结构

Boss 阶段表记录 Boss 阶段切换规则。

| 中文字段 | 英文字段 | 说明 | 类型或取值 | 示例 |
|---|---|---|---|---|
| Boss ID | `boss_id` | 引用敌人表中 `enemy_type = boss` 的 `enemies.id`。 | 已存在的 Boss 敌人 ID | `boss_forest_guardian` |
| 阶段 ID | `phase_id` | Boss 阶段的程序标识，被 Boss 阶段卡组引用。 | 小写英文、数字、下划线 | `phase_1` |
| 是否默认阶段 | `is_default` | 标记 Boss 进入战斗时默认使用的阶段。每个 Boss 必须且只能有一个默认阶段。 | 布尔值 | `true` |
| 触发条件类型 | `condition_type` | 阶段切换条件类型。默认阶段使用 `default`，非默认阶段第一版使用生命阈值。 | `default`、`hp_below_or_equal` | `hp_below_or_equal` |
| 生命阈值 | `hp_value` | 非默认阶段的生命触发阈值。`condition_type = default` 时不参与判断，统一填 `0`。 | 非负整数 | `20` |
| 每回合最大出牌数 | `max_cards_per_turn` | Boss 在该阶段每回合最多可使用的卡牌数量。 | 正整数 | `2` |
| 备注 | `note` | 给设计和调试使用的说明，不参与战斗结算。 | 文本或空 | `半血后进入第二阶段` |

Boss 阶段卡组仍然写在 `enemy_decks` 中。

Boss 进入战斗时直接进入 `is_default = true` 的阶段，不通过 HP 条件判断进入默认阶段。

非默认阶段才参与阶段切换判断。PVE 第一版阶段切换单向执行，Boss 因治疗回到阈值以上时，不回退到默认阶段。

## 11. 关卡敌人摆放数据结构

关卡敌人摆放表记录某张关卡地图上放了哪些敌人。

| 中文字段 | 英文字段 | 说明 | 类型或取值 | 示例 |
|---|---|---|---|---|
| 地图 ID | `map_id` | 引用地图表中 `map_type = level_map` 的 `maps.id`。 | 已存在的关卡地图 ID | `level_map_001` |
| 关卡敌人实例 ID | `level_enemy_id` | 关卡地图上某个敌人实例的唯一标识。用于记录该实例是否已击败。 | 小写英文、数字、下划线 | `level_enemy_001` |
| 敌人 ID | `enemy_id` | 引用敌人表中的 `enemies.id`，表示该实例使用哪种敌人数据。 | 已存在的敌人 ID | `enemy_slime` |
| 出生点 | `spawn_point` | 敌人在关卡地图上的出现位置，可以是点位 ID 或坐标。 | 点位 ID 或坐标 | `enemy_spawn_001` |
| 是否 Boss | `is_boss` | 标记该敌人实例是否为 Boss，用于流程胜利判断和地图表现。 | 布尔值 | `false` |
| 默认已击败 | `defeated_default` | 新开局时该敌人实例是否默认已被击败。第一版通常为 `false`。 | 布尔值 | `false` |

PVE 从关卡地图碰撞敌人进入战斗。

因此 `level_enemies` 是连接关卡地图、敌人数据和战斗流程的关键表。

## 12. 引用关系

当前主要引用关系：

```text
hero_decks.hero_id → heroes.id
hero_decks.card_id → cards.id

card_levels.card_id → cards.id

enemy_decks.enemy_id → enemies.id
enemy_decks.card_id → cards.id

boss_phases.boss_id → enemies.id

level_enemies.map_id → maps.id
level_enemies.enemy_id → enemies.id
```

规则：

- 引用必须指向存在的 ID
- 被引用对象不应为空
- 禁止在卡组表中复制卡牌完整数据
- 禁止在关卡敌人表中复制敌人完整数据

## 13. Godot 运行数据建议

Godot 运行数据建议使用：

```text
data/
├── cards.json
├── heroes.json
├── enemies.json
├── maps.json
└── level_enemies.json
```

运行数据应将分散配置合并为游戏更方便读取的结构。

例如角色导出时可以合并：

- `heroes`
- `hero_decks`
- `cards`
- `card_levels`

敌人导出时可以合并：

- `enemies`
- `enemy_decks`
- `cards`
- `card_levels`
- `boss_phases`

如果后续需要从 `config/records/` 自动生成 `data/*.json`，优先在 Godot 内实现导入工具或编辑器脚本。

## 14. 数据校验规则

后续 Godot 数据校验入口至少检查：

- ID 是否为空
- ID 是否重复
- 引用 ID 是否存在
- `card_levels.level` 是否超过卡牌 `max_level`
- `hero_decks.level` 是否超过卡牌 `max_level`
- `enemy_decks.level` 是否超过卡牌 `max_level`
- `cards.owner` 是否为合法枚举
- `cards.rarity` 是否为合法枚举
- `cards.release_type` 是否为合法枚举
- `cards.target` 是否为合法枚举
- `heroes.max_hp` 是否大于 0
- `enemies.max_hp` 是否大于 0
- `max_energy` 是否大于等于 `initial_energy`
- `level_enemies.map_id` 是否指向关卡地图
- `level_enemies.enemy_id` 是否指向敌人
- Boss 阶段是否引用 `enemy_type = boss` 的敌人
- 每个 Boss 是否有且只有一个 `is_default = true` 的阶段
- Boss 默认阶段的 `condition_type` 是否为 `default`
- Boss 非默认阶段的 `condition_type` 是否为有效切换条件，且 `hp_value` 是否有效

## 15. 第一阶段必须具备的数据

第一阶段单人 PVE 至少需要：

- 1 个角色
- 角色初始卡组
- 玩家卡牌和等级数值
