# 战斗地图界面 core 1 完善设计

- 日期：2026-07-02
- 范围：`MyGame` 的「战斗地图界面」关卡与 UI 表达
- 状态：设计确认，待实施

## 1. 背景

`策划案/core 1` 明确战斗地图是所有战斗发生的空间，负责单位出生点、单位站位、导航网络、障碍物、卡牌释放范围、释放方向、目标检测和技能范围判定。

当前项目中已经存在：

- `MyGame/UI/战斗地图界面.ui`：顶栏、回合提示、筛选按钮、手牌区、结束回合按钮。
- `MyGame/Levels/战斗地图界面.level`：主摄像机、四面墙、背景、3 个示例单位。
- `MyGame/UI/头顶信息.ui`：头顶血条和蓝条。
- 关卡蓝图中已有 `UI.Follow`，可以让头顶信息跟随示例单位。

本次完善不是重做界面，而是在现有骨架上补齐战斗地图的空间可读性，让玩家和后续调试都能看懂“哪里能站、从哪里出生、什么会阻挡、卡牌释放覆盖哪里、哪些目标合法”。

## 2. 产品目标

本阶段目标是完成一个可运行、可查看、可继续接战斗逻辑的战斗地图界面骨架。

验收时应能看到：

- 中央战场不是空背景，而是明确的战斗地图区域。
- 地图内有导航网格或可通行区域提示。
- 我方与敌方出生区域可见。
- 障碍物可见，并与四面墙共同表达战场边界。
- 示例单位分布在战场中，每个单位有头顶血条和蓝条。
- 拖拽卡牌释放的后续挂载点可见：释放范围预览、合法目标高亮。
- 底部保留现有手牌区、筛选按钮和结束回合按钮。

## 3. 非目标

本阶段不实现完整战斗结算。

明确不做：

- 真实卡牌拖拽释放与结算。
- 真实寻路算法和导航网络编辑器。
- AI 自动出牌。
- 伤害、治疗、护盾、能量恢复等数值结算。
- 胜负结算和返回关卡地图流程。
- 牌库、弃牌堆弹窗。

本阶段只做静态或半静态界面表达与运行时展示挂载点，后续战斗逻辑可以复用这些命名和控件。

## 4. 设计方向

采用“地图优先”方案。

理由：

- `core 1` 对战斗地图的要求集中在空间逻辑：出生点、站位、导航、障碍、释放范围和目标检测。
- 当前 UI 已经有手牌区和顶栏，最缺的是战斗空间本身的可读性。
- 先把地图表达做清楚，后续接真实卡牌释放和战斗节点时更容易验证范围与目标。

## 5. 界面结构

### 5.1 顶部信息栏

沿用现有 `信息栏背景`、`角色名称`、`HP条`、`MP条`、`牌库按钮`、`弃牌按钮`、`金币数`、`设置`。

调整原则：

- 对外文案继续使用中文。
- 顶部信息栏展示当前玩家角色的战斗状态。
- `能量底板` 与 `能量数值` 保留为第一阶段战斗规则所需的能量显示。
- 若后续确认“蓝条”和“能量”合并，应在战斗规则阶段再统一；本阶段不删除现有控件，避免破坏已存在蓝图挂载点。

### 5.2 中央战斗地图

在 `战斗地图界面.level` 中强化中央战场表达。

需要呈现：

- 四面墙：继续使用 `墙_上`、`墙_下`、`墙_左`、`墙_右`，作为战场边界。
- 战场底图：替换或覆盖当前登录背景图，让它更像战斗场地。
- 导航网格：用若干半透明线条或示例格子表达可通行区域。
- 我方出生区：位于战场左侧，命名为 `出生区_team_1`。
- 敌方出生区：位于战场右侧，命名为 `出生区_team_2`。
- 障碍物：至少放置一个示例障碍，命名为 `障碍_中央`，用于表达阻挡规则。
- 示例单位：保留或重命名现有 3 个单位为 `我方单位_武夫`、`敌方单位_疯子`、`敌方单位_污染兽`。

### 5.3 范围与目标挂载点

本阶段新增可见但不结算的挂载点：

- `释放范围预览`：半透明矩形或扇形区域，用于表达范围卡牌释放时覆盖区域。
- `合法目标高亮`：目标单位周围的高亮圈，用于表达命中目标。

这些对象默认可见，用于验收和后续蓝图接线；后续真实拖拽释放阶段再改为按交互显示和隐藏。

### 5.4 头顶信息

沿用 `头顶信息.ui` 与关卡蓝图中的 `UI.Create` + `UI.Follow` 方案。

本阶段要求：

- 每个示例单位都有头顶血条和蓝条。
- 头顶信息不遮挡单位主体。
- 控件命名保持中文，方便后续蓝图引用。

### 5.5 底部操作区

沿用现有：

- `筛选_全部`
- `筛选_攻击牌`
- `筛选_技能牌`
- `筛选_状态牌`
- `手牌区`
- `结束回合`

调整原则：

- 保留静态示例卡牌。
- 已用卡继续置灰。
- `结束回合` 保持在右下、手牌区上方，避免和手牌滚动区域重叠。

## 6. 数据与命名约定

战斗地图相关对象使用中文名对外表达，内部 ID 可保持现有 UUID。

建议命名：

| 对象 | 名称 |
|---|---|
| 我方出生区 | `出生区_team_1` |
| 敌方出生区 | `出生区_team_2` |
| 中央障碍 | `障碍_中央` |
| 导航网格 | `导航网格_*` |
| 释放范围 | `释放范围预览` |
| 合法目标 | `合法目标高亮` |
| 玩家示例单位 | `我方单位_武夫` |
| 敌方示例单位 1 | `敌方单位_疯子` |
| 敌方示例单位 2 | `敌方单位_污染兽` |

本阶段不新增新的底层配置表，不修改 `策划案/core 1` 的规则文档。

## 7. 运行时流程

进入 `战斗地图界面.level` 后：

1. 关卡开始运行。
2. 创建 3 个 `头顶信息` UI 实例。
3. 分别绑定到我方单位、敌方单位 1、敌方单位 2。
4. 显示战斗地图 UI。
5. 点击 `结束回合` 时，现有蓝图可以继续把回合提示改成「敌方回合」并打印调试信息。

## 8. 实现约束

- 不新增 C++ 引擎能力，除非现有资源无法表达上述静态挂载点。
- 优先修改 `MyGame/Levels/战斗地图界面.level` 和 `MyGame/UI/战斗地图界面.ui`。
- 如需新增 `.cpp` 或 `.h`，必须同步更新 `launcher/CMakeLists.txt`，但本设计预期不需要新增源码。
- 修改 `.level` 或 `.ui` 后，应启动应用验证运行时显示。
- 若修改 `.cpp`、`.h`、`.qss`、`.qrc`，必须重新编译并运行应用验证。

## 9. 验收标准

完成后至少验证：

- 编译成功并能启动 `launcher.app`。
- 打开 `MyGame` 后能进入「战斗地图界面」。
- 游戏预览中能看到战斗地图 UI。
- 中央战场可见，不是空白或登录背景主导。
- 战场内能看到我方出生区、敌方出生区、障碍、导航网格、释放范围预览和合法目标高亮。
- 三个示例单位可见，并分别有头顶血条和蓝条。
- 底部手牌区、筛选按钮、结束回合按钮布局不互相遮挡。
- 点击结束回合后，回合提示能按现有蓝图变成「敌方回合」。

## 10. 风险

- `.level` 和 `.ui` 是 JSON 文件，手工编辑容易破坏格式；实施时应使用脚本或结构化 JSON 处理，并在保存后检查可解析性。
- 当前工作区已有多处未提交改动，实施时不得回退无关修改。
- 如果当前界面资源已经被用户在编辑器中打开并另存，实施前后需要以磁盘文件为准，避免覆盖用户同时编辑的内容。
