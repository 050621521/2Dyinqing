# 蓝图通用变量 / 数据 / 运算能力（引擎特性 #1+#2）设计

日期：2026-06-22

## 背景与定位

本设计是**引擎能力完善**，不是做某款游戏。起因是评估"用本引擎做 2D 卡牌战斗游戏（回合制、单人 PVE 起步）还缺什么"，该用例照出引擎一批通用缺口：

| # | 引擎能力 | 现状 |
|---|---|---|
| 1 | 类型化变量 + 数组 + 遍历 | 只有字符串标量全局变量 |
| 2 | 数学 / 比较 / 逻辑运算节点 | 完全没有 |
| 3 | 运行时生成/销毁对象 | 仅静态摆放 |
| 4 | 自定义事件 / 事件分发 | 仅 开始运行/按键 |
| 5 | 数据资产系统 | 无 |
| 6 | 蓝图类实例化增强 | 有雏形 |
| 7 | 计时器/延时 + 补间动画 | 仅瞬移 |

**原则**：引擎只提供通用积木，不把"卡牌/能量/召唤物"等游戏规则焊入引擎。游戏逻辑由用户用蓝图 + 数据自行拼装。

**本 spec 范围**：仅 #1 + #2。它们是地基中的地基——把蓝图从"摆场景的脚本"升级成"能写真正游戏逻辑的语言"，#3~#7 都建立在其上。#3~#7 为后续独立 spec。

## 现状摸底（设计依据）

- `BPNode.params` 为 `QMap<QString,QString>`（编辑器手填字面量，全字符串）。
- 运行时变量表 `m_varStore`、全局变量表 `m_globalVars` 均为 `QMap<QString,QString>`。
- 数据引脚求值 `BPRuntime::resolveDataPin()` / `resolveOutputPin()` 当前返回 `QString`。
- exec 链 `executeChain()` 前向遍历，用 `visited` 集合防重入；`executeNode()` 执行单节点。
- 引脚已有 `ValueKind` 类型标签（`Text` / 各种 Ref），且支持"按节点实例推导引脚"（`enumValuesForPin`，`EnumRef`）。
- 变量声明 `GlobalVarDef{name,type}`，type 取 `number/bool/string/enum:<名>`，存 `project.json`。

## 核心决策：类型化值 `BPValue`（方案乙）

引入标签联合体 `BPValue`，运行时数据引脚与变量都用它承载真实类型。

| 类型 | 底层 | 说明 |
|---|---|---|
| `Number` | `double` | 统一数值，不分 int/float |
| `Bool` | `bool` | |
| `String` | `QString` | 也承载"对象名引用"等（按名字找 Actor 的约定不变） |
| `Array` | `QList<BPValue>` | 异构容器，可嵌套 |
| `Null` | — | 空/未赋值 |

### 强制转换（coercion，集中一处定义）
`BPValue` 提供 `toString() / toNumber() / toBool()`，互转规则集中定义，是控制改动面的关键：
- `Number→String`：格式化（去除多余尾零）。
- `String→Number`：解析失败 → `0`。
- `Array→String`：转 JSON 字符串。
- `Bool→Number`：true=1 / false=0；`Number→Bool`：非 0 为 true。
- `Null` 参与运算按 `0 / false / ""` 处理。
- 除以 0 → `0`。

### 迁移策略（不炸现有蓝图）
1. `resolveDataPin()` / `resolveOutputPin()` 返回类型 `QString` → `BPValue`。
2. 所有**现存**调用点（Print、MoveActor 等）取值处加 `.toString()`，行为不变。
3. `m_varStore` / `m_globalVars` 改为 `QMap<QString,BPValue>`；`BPNode.params` **仍存字符串**，运行时按引脚类型解析为 `BPValue`——**存档格式零改动**。
4. 引脚 `ValueKind` 新增 `Number / Bool / Array / Any`；数组引脚附带"元素类型"标签，仅供编辑器配色与连线校验，运行时不强制。

## 变量系统升级

### 类型化声明
现有类型扩展出**数组类型** `array:<元素类型>`，如 `array:number`、`array:string`、`array:enum:敌人类型`。声明里数组仅一层（运行时 `BPValue` 仍可嵌套）。

### 作用域：全局 + 局部（新增局部）
| 作用域 | 存储 | 可见范围 | 生命周期 |
|---|---|---|---|
| 全局（已有） | `project.json` | 所有蓝图 | 运行期常驻 |
| 局部（新增） | 所在蓝图文档内 | 仅本蓝图图表 | 每次运行重置 |

> 实例变量（每实例一份，如各召唤物自己的 HP）属 #6 BPClass 增强，本 spec 不做，预留口子。

### Get/Set 节点
- 保留 `获取全局变量` / `设置全局变量`（支持新增数组类型）。
- 新增 `获取变量` / `设置变量`（操作局部变量）。
- `设置…` 为 exec 节点（exec 入→出贯通）；`获取…` 为纯数据节点。

### 动态引脚类型（关键 UX）
节点选中某变量后，其数据引脚 `ValueKind` 跟随该变量声明类型变化（选 `number`→Number 引脚，选 `array:string`→Array 引脚），供下游即时类型校验/配色。复用现有"按节点实例推导引脚"机制（`enumValuesForPin` 那套）。

### 声明 UI
- 扩展 `GlobalVarPanel` 支持声明数组类型。
- 新增局部变量声明入口（蓝图编辑器内的变量列表面板，写入蓝图文档）。
- 变量声明支持**默认值**（数组字面量初始元素由此填，不做变长输入的"创建数组"节点）。

## 运算节点（数学 / 比较 / 逻辑）

全为**纯数据节点**（无 exec），靠现有拉取式求值（`resolveOutputPin` 被下游拉取时即时计算）。运算符用节点上的**下拉参数**（存 `node.params["op"]`），避免节点面板膨胀。

| 节点（中文名） | 运算符（下拉） | 输入 | 输出 | 说明 |
|---|---|---|---|---|
| 数值运算 | `+ − × ÷ 取余` | A, B (Number) | 结果 (Number) | 除 0 → 0 |
| 比较 | `> ≥ < ≤ = ≠` | A, B (Any) | 结果 (Bool) | 大小比较按 `toNumber`；`=/≠` 类型感知相等 |
| 逻辑 | `与 / 或` | A, B (Bool) | 结果 (Bool) | 二元 |
| 取反 | —（一元） | A (Bool) | 结果 (Bool) | 单独节点 |

### 引脚与连线协调
- 比较节点输入用 `Any` 引脚（接受任意值、不强制配色）；运行时按运算符解释：排序类强制 `toNumber`，相等类按 `BPValue` 类型感知相等。
- 跨类型连线规则（编辑器层）：同类型=干净连接；标量跨类型（如 Number→String）=允许但显示"自动转换"提示，运行时 `BPValue` 转换兜底；**数组↔标量=禁止连接**。
- 因 `BPValue` 自带转换，**暂不做"转文本/转数值"节点**（隐式转换已覆盖）；将来有"指定数字格式"等需求再加，列为可选。

## 数组节点 + 遍历(ForEach)

### 数组数据节点（纯数据，作用于流入的数组值）
| 节点 | 输入 | 输出 | 边界 |
|---|---|---|---|
| 创建空数组 | — | 数组 (Array) | — |
| 数组长度 | 数组 | 长度 (Number) | 空→0 |
| 获取元素 | 数组, 索引(Number) | 元素 (Any) | 越界→Null |
| 包含 | 数组, 值 | 结果 (Bool) | 类型感知相等 |

### 数组变量操作节点（exec，针对选定的数组变量）
复用 Set 节点的变量选择器，节点内部做"读→改→写回"，仅可选数组类型变量（动态引脚校验）。exec 入→出贯通。
| 节点 | 参数/输入 |
|---|---|
| 添加元素 | 目标变量, 值 |
| 移除元素 | 目标变量, 运算符下拉(按索引/按值), 索引或值 |
| 设置元素 | 目标变量, 索引, 值 |
| 清空数组 | 目标变量 |

### 遍历(ForEach) —— 唯一改动 exec 执行链处
节点 **遍历数组** 引脚：
- exec 入；数据入：数组(Array)
- exec 出 **循环体**（每元素触发一次）
- 数据出（仅循环体内有效）：当前元素(Any)、当前索引(Number)
- exec 出 **完成**（全部迭代后触发一次）

运行时改造要点：
1. **visited 冲突**：循环体每次迭代用**独立 visited 上下文**，否则第二次迭代体内节点被当成"已执行"而跳过。
2. **迭代状态存储**：ForEach 运行时维护 `QMap<nodeId,{当前元素,当前索引}>`；循环体内"当前元素/索引"输出引脚读它，出循环后清除。
3. **嵌套循环**：状态按 nodeId 存 → 天然支持嵌套。
4. **快照迭代**：循环开始时对数组取快照再遍历，避免体内修改原变量导致迭代错乱。
5. **空数组**：循环体 0 次，完成触发 1 次。
6. **break/continue 不做**（YAGNI）；体内用条件分支自行规避。
7. 纯数据节点拉取式求值不受影响，**仅 exec 链此一处改动**。

## 影响文件（预估）

- `src/editor/BPRuntime.{h,cpp}`：`BPValue` 类型；求值返回类型改造；变量表类型；ForEach 执行链与迭代状态；运算/数组节点求值。
- `src/editor/BlueprintEditor.{h,cpp}`：`ValueKind` 扩展（Number/Bool/Array/Any）；新节点的 `NodeDef`；运算符下拉参数；动态引脚推导；跨类型连线校验与配色；局部变量面板。
- `src/editor/GlobalVars.{h,cpp}` / `GlobalVarPanel`：数组类型声明、默认值、局部变量声明存储。
- `src/models/LevelDocument.{h,cpp}`：局部变量声明随蓝图文档持久化（params 字符串格式不变）。
- `CLAUDE.md` 术语表：补充新节点中文名。
- `src/editor/ActorBPRuntime` 等其它使用 `resolveDataPin` 的运行时：同步 `.toString()` 迁移。

## 不在本 spec 范围（YAGNI / 后续）

- #3 运行时生成/销毁、#4 自定义事件、#5 数据资产表、#6 实例变量与 BPClass 增强、#7 计时器/补间。
- 显式类型转换节点、min/max/abs 等扩展数学、indexOf/排序等扩展数组操作、ForEach 的 break/continue。
- 方案乙之外的性能优化（当前无性能压力）。

## 验收标准

- 能声明 number/bool/string/数组 的全局与局部变量，含默认值。
- 蓝图里可用数值运算/比较/逻辑/取反节点拼出条件表达式（如"A>0 且 B≤10"）并驱动条件分支。
- 能对数组变量增删改、取元素、判包含、读长度。
- ForEach 能正确遍历数组、循环体内读到当前元素/索引、空数组与嵌套循环行为符合上文定义。
- 所有现存蓝图（Print/MoveActor 等）运行行为不变，旧存档可正常打开。
