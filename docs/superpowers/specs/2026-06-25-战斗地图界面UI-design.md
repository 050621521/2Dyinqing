# 战斗地图界面 UI 设计

- 日期：2026-06-25
- 范围：MyGame「战斗地图界面」的**界面与场景骨架**
- 状态：设计定稿，待实现

---

## 1. 目标与范围

本次只做战斗地图界面的**静态界面 + 场景骨架**：把屏幕上该有的东西按布局摆好、接上能直接读到的数据（如玩家角色名、血、法力）。

**不在本次范围**（留到下一阶段「战斗逻辑」）：
- 出牌、卡牌效果结算、伤害/治疗计算
- 单位移动、位移类卡的落点选择
- 回合推进、敌方 AI、召唤
- 金币的真实增减（本版仅占位显示）

界面要为后续逻辑留好「挂载点」（控件命名清晰、数据绑定位置明确），但逻辑本身不实现。

---

## 2. 已锁定的战斗机制（决定界面长这样的前提）

| 机制 | 规则 |
|---|---|
| 战场形态 | **自由战场**：关卡里四面墙（`墙_上/下/左/右`）围出竞技场，双方单位散落自由站位，**无前后排、无固定点位** |
| 移动 | 单位靠**卡牌**移动，部分卡带位移能力 |
| 回合 | 回合制（玩家回合 / 敌方回合） |
| 法力（蓝） | **整场一个大池子，只降不升、永不回复**；出牌按卡面消耗扣蓝 |
| 卡牌使用 | 每张卡**一场只能用一次**，且当前蓝量足够才能出 |
| 卡牌分类 | 攻击牌 / 技能牌 / 状态牌（顶部可筛选） |
| 单位规模 | N 对 N，含召唤；双方场上单位（含召唤物）各上限 3 |
| 不做 | **无意图提示、无能量条** |

│                                          ╰─────────╯      │  ← 右下、手牌区上方
├─────────────────────────────────────────────────────────┤

界面分三层：
1. **场景层**：关卡 `战斗地图界面.level` 里的竞技场与单位（Actor，世界空间）
2. **UI 层**：`战斗地图界面.ui` 里的信息栏、筛选、手牌区、回合提示、结束回合（屏幕空间）
3. **头顶条**：跟随单位的血条/蓝条（见 §5 实现考量）

## 4. UI 控件详细映射

落到引擎现有控件类型（面板 / 文本 / 图片 / 按钮 / 进度条 / 下拉菜单 / 横向布局 / 竖向布局 / 网格布局 / 滚动视图）。

### 4.1 顶部信息栏

| 元素 | 控件类型 | 内容 / 数据来源 | 本版状态 |
|---|---|---|---|
| 信息栏背景 | 面板 | 顶部横条容器 | 静态 |
| 角色名称 | 文本 | **固定为玩家所选角色**：读全局变量 `角色`（0=武夫，1=机械师），不随点击切换 | 接数据 |
| 血条 | 进度条 | 该角色当前血 / 最大血（武夫读 `wufu_HP`，机械师同理后续补） | 接数据 |
| 蓝条 | 进度条 | 整场法力池当前 / 上限 | 接数据 |
| 金币UI | 图片 | 金币图标 | **占位** |
| 金币数 | 文本 | 金币数量 | **占位**（先显示固定数，后续接真实值） |
| 牌库 | 按钮 | 打开牌库（功能后续） | 占位按钮 |
| 设置 | 按钮 | 打开设置（功能后续） | 占位按钮 |

名称、血条、蓝条建议用一个横向布局打包；牌库、设置靠右。

### 4.2 回合提示

- 控件：文本（可加面板做底色）
- 位置：顶栏下方居中
- 内容：「玩家回合」/「敌方回合」，本版固定显示「玩家回合」

### 4.3 结束回合

- 控件：按钮
- 位置：右下、手牌区上方
- 功能后续，本版为占位按钮

### 4.4 底部筛选标签

- 控件：4 个按钮（全部 / 攻击牌 / 技能牌 / 状态牌），建议横向布局
- 选中态视觉高亮（「全部」默认选中）
- 本版仅做按钮与高亮样式，过滤逻辑后续

### 4.5 手牌区

- 容器：滚动视图 + 内嵌横向布局，支持横向滚动
- 每张卡（卡牌控件，本版用面板+文本/图片拼）：
  - 卡名、简述
  - 法力消耗角标（右上角，蓝色圆点 + 数字）
  - 状态：正常 / 已用（置灰）/ 蓝不够（变暗，可后续阶段加）
- 本版摆静态示例卡，真实手牌生成与出牌后续接逻辑

## 5. 头顶血条 / 蓝条（实现考量）

需求：**战场上每个单位**（玩家角色、召唤物、敌人）头顶都有一条血条 + 一条蓝条，跟随单位在战场移动。

引擎现状：UI 系统是**屏幕空间锚点**布局，单位是**世界空间** Actor。让 UI 控件持续跟随世界里的对象，引擎当前可能不支持。两条候选路线：

- **路线 A（推荐先评估）**：补一个「世界跟随」能力——UI 控件可绑定某 Actor，运行时按其世界坐标换算到屏幕位置实时定位。属于通用引擎能力，后续别的需求也用得上。符合「遇引擎缺口先补引擎」原则。
- **路线 B（兜底）**：头顶条用**精灵/子 Actor** 实现，作为单位的子物体跟着动，不走 UI 系统。

本设计**标记此为待定实现点**，不阻塞界面定稿；进入实现阶段时先确认引擎能力再二选一。
