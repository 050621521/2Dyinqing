# 复现录制机制设计

日期:2026-06-19

## 背景与目标

当前修复 bug 的流程中,用户口头报告问题后,AI 缺三样关键信息:精确操作序列、当时的应用状态、用户期望与实际画面的差异。信息缺失导致同一个问题反复来回沟通才能修复。

本机制让用户在引擎里**手动复现一遍问题**,过程被完整记录为一份 AI 可直接读取的 Markdown 文件,从而一次性把"复现步骤 + 实际状态 + 控制台输出"交给 AI。

### 能力边界(明确写清,避免高估)

| 修复所需信息 | 本机制能否提供 | 说明 |
|---|---|---|
| 精确复现步骤 | ✅ 完整 | 语义化操作时间线 |
| 当时的实际状态 | ✅ 完整 | 状态快照 + 控制台日志 |
| 用户的"期望"是什么 | ❌ 给不了 | 录制只记录实际发生,用户仍需一句话说明期望 |
| 画面渲染是否正确 | ⚠️ 部分 | 纯文字无法暴露"数据对但画面错";靠按需截图补 |

因此本机制覆盖"逻辑 / 交互 / 状态"类 bug;渲染正确性类 bug 由 AI 读完记录后**主动向用户索取某一刻截图**补全。

## 两个被专门处理的盲区

1. **渲染正确性(数据对、画面错)**:记录文件不内嵌截图。AI 读完时间线/快照后,若怀疑是绘制层问题(如 `worldToScreen`、绘制顺序),主动找用户要对应时刻的截图。
2. **帧级/时序问题(过程中的抖动、震荡)**:bug 常藏在拖动/缩放的中间帧(如靠近边缘的吸附反馈震荡)。录制激活期间,对连续操作(`actorDragging`、缩放)记录**每帧的中间值(含吸附前/后)**,而非仅记首尾;连续相同值自动合并以防刷屏。

## 架构与数据流

```
                        ┌─────────────────────────┐
  各面板信号 ──────────▶│   EditorWindow 埋点      │
 (已集中连接的那批)      │  Recorder::log(...)      │
                        └───────────┬─────────────┘
                                    ▼
qDebug/蓝图打印 ──qInstallMessageHandler──▶ ┌──────────────┐
                                            │  Recorder    │ 单例
LevelDocument/BPRuntime ──snapshot()──────▶ │  (内存缓冲)   │
                                            └──────┬───────┘
                                  start/stop 按钮   ▼
                                          写出 latest.md + 时间戳文件
```

### Recorder 单例

职责单一:收集录制条目并在停止时写出文件。

接口:
- `startRecording()`:清空缓冲、记起始时间、接管 `qInstallMessageHandler`(链式调用旧 handler,不影响正常打印输出)、记录初始环境(关卡、PPU、当前工具)。
- `stopRecording()`:还原原 message handler、写出文件、返回文件路径。
- `log(category, text)`:追加一条带相对时间戳的时间线条目。连续相同内容自动合并(用于帧级中间值)。
- `snapshot(label)`:从 `LevelDocument` / `BPRuntime` 拉取当前状态,追加一段状态快照。
- `isRecording()`:供 UI 显示红点/计时与决定是否记录帧级事件。

依赖:`LevelDocument`(取 Actor 列表/坐标/层级)、`BPRuntime`(取运行时变量/快照)、`ProjectInfo`(取记录文件存放目录)。不反向依赖任何 UI 组件。

### 埋点位置

全部放在 `EditorWindow` **已集中连接信号**的位置,不散落进各面板内部,保持单一改动面:
- 工具切换(`setToolMode`)
- Actor 选中(`SceneOutliner::actorSelected` / `Viewport2D::setSelectedId`)
- Actor 拖动:开始 / 帧级中间值 / 结束(`Viewport2D::actorDragging`、`actorTransformed`)
- Actor 创建(`actorCreated`)
- 细节面板字段修改(`DetailsPanel::actorModified`)
- Tab 切换 / 关卡切换
- 运行控制(`startRuntime` / `stopRuntime`)
- 运行时打印(`BPRuntime` 的 print 输出)

### 自动快照时机

无需额外按钮,以下节点自动 `snapshot()`:开始录制、停止录制、点运行、停运行、切关卡。

## 记录文件格式(Markdown)

选 Markdown 而非 JSON:对 AI 和用户都直接可读,无需解析。

```markdown
# 复现录制 2026-06-19 14:32:01
环境: 关卡 Levels/Main.level | PPU 1 | 工具 选择

## 时间线
[00:00.000] 工具 → 移动
[00:00.500] 选中 "Player" (id=3)
[00:01.200] 拖动开始 "Player" 起点(0.0, 0.0)
[00:01.21]    ↳帧 吸附前(1.2,0.0)→吸附后(1.0,0.0)
[00:02.000] 拖动结束 "Player" 终点(5.0, 3.0)
[00:03.000] ▶运行
[00:03.10]  打印 "血量=100"

## 状态快照 @00:03.000 运行前
- Player (精灵) pos(5,3) rot0 scale(1,1) 层=Default order=0
- Camera (摄像机) pos(0,0) main=true size=540

## 控制台日志
[qDebug] BPRuntime: triggerBeginPlay ...
```

时间线、状态快照、控制台日志三段。所有操作名、Actor 类型名、节点名按项目中文术语表书写(如"移动""精灵""开始运行")。

## 存放与交接

- **路径**:`{当前项目}/.recordings/recording-<时间戳>.md`,同时覆盖一份 `{当前项目}/.recordings/latest.md`。
- **交接流程**:用户点"停止",引擎弹提示显示文件绝对路径并复制到剪贴板。用户只需说"录好了",AI 即 glob 最新的 `**/.recordings/latest.md`(按 mtime 取最新)并 Read,无需用户贴路径。

## UI

视口工具栏新增一个**红点录制按钮**:
- 未录制:灰色红点图标,提示"开始复现录制"。
- 录制中:常亮红点 + 计时显示,点击停止并弹出文件路径提示。

## 测试

- 单元层面:`Recorder::log` 的连续相同值合并、相对时间戳计算、message handler 链式还原。
- 集成层面:开始录制 → 选中/移动一个 Actor → 运行 → 停止,验证生成的 `latest.md` 含完整三段且内容正确。
- 手动验证:按 CLAUDE.md 流程编译运行,实际录一遍拖动操作,确认帧级中间值被记录且连续相同值已合并。

## 非目标(YAGNI)

- 不做视频/屏幕录制(AI 无法消费)。
- 不做全局 `QApplication` 事件过滤器(原始像素事件信噪比太低)。
- 不做后台环形缓冲(本期仅手动开始/停止)。
- 不内嵌截图(按需向用户索取)。
- 不做录制回放/自动重放(本期只为给 AI 提供信息,不做自动化测试驱动)。
