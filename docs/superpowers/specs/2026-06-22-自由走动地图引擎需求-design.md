# 自由走动地图界面 · 引擎需求设计

- 日期：2026-06-22
- 状态：已确认，待实现
- 范围：仅引擎侧改动，服务于「标准地图界面（自由走动式）」

## 背景

正在用本引擎制作一款回合制卡牌游戏（先做单人 PVE）。完整流程：

```
登录界面 → 单人模式 → 角色选择界面 → 标准地图界面 → 标准战斗界面
```

当前阶段：实现**标准地图界面**。采用**自由走动式**——玩家像 RPG 大地图那样，用方向键控制角色小人在地图上自由移动，地图上散布「敌人节点」和「其他交互节点」，角色走到敌人节点附近即进入战斗界面。

本设计遵循「按游戏开发进度倒逼引擎完善」的原则：只补做这一阶段真正缺的引擎能力，不为扩展而扩展。

## 能力盘点

### 引擎已具备（直接复用，不改动）

| 能力 | 现状 |
|---|---|
| 角色移动 | 节点 `获取自身位置` / `设置自身位置` / `移动对象` 均可用 |
| 摄像机跟随 + 边界限制 | 运行时已实现：摄像机 `followTarget` 平滑跟随 + `confiner` 边界夹取（`BPRuntime` 内） |
| 进入战斗 | `跳转关卡`（`Action.LoadLevel`）可用 |

| 角色不越界 | 用现有 `数值夹取`（`Math.Clamp`）夹取坐标即可，无需碰撞系统 |

### 需要的引擎改动（共两项）

只缺两项，详见下文。**距离/接近检测不改引擎**，用现有节点组合实现（见「不改引擎的部分」）。

## 改动 1：「每帧」事件节点上菜单

### 现状
运行时**已完全支持** `Event.Tick`：
- `BPRuntime` 构造时启动 16ms 定时器，每帧调用 `tick()` → `triggerTick(dt)`，遍历执行所有 `Event.Tick` 节点的执行链（见 `editor/BPRuntime.cpp`）。
- `Event.Tick` 节点的 `delta_time` 数据输出引脚也已在运行时实现求值（`editor/BPRuntime.cpp` 中 `m_deltaTick`）。
- `ActorBPRuntime` 同样支持 `Event.Tick`。

唯一缺失：`BlueprintEditor::nodeDefs()` **没有注册** `Event.Tick`，所以右键菜单加不出这个节点，蓝图无法使用。

### 改动
在 `editor/BlueprintEditor.cpp` 的 `nodeDefs()` 列表中新增一条：

- typeId：`Event.Tick`
- 中文显示名：**每帧**
- header 颜色：事件紫 `#6a2a8a`（与其他 Event 节点一致）
- 引脚：
  - `exec_out`（执行输出）
  - `delta_time`（数据输出，数值类型）—— 引脚中文名「帧间隔」

### 验收
- 右键菜单可添加「每帧」节点。
- 运行时每帧触发其执行链。
- `帧间隔` 引脚能输出当前帧的 dt（约 0.016）。

### 风险
极低。运行时是现成的，仅补节点定义。

## 改动 2：按键节点新增「持续按住」引脚

### 概念澄清
按键有两个**跳变事件**（按下 Pressed / 松开 Released），但也有一个**持续状态**（按下到松开之间一直「按住中」）。平滑移动需要的是这个持续状态——这正是虚幻引擎 Axis 每帧触发 / `Is Input Key Down` 所做的事。仅靠按下/松开两个瞬间事件做移动会受系统按键重复延迟影响，移动一顿一顿的。

本设计采用**形态甲**：在现有按键节点上直接增加一个每帧触发的执行引脚，而非新增独立查询节点。

### 现状
- 全部 13 个按键节点：`Event.Key.W/A/S/D/Up/Down/Left/Right/Space/Return/Escape/Shift/Control`，当前引脚为 `{按下(pressed), 松开(released)}`（见 `nodeDefs()`）。
- 运行时：`BPRuntime::triggerKeyDown(key)` 执行 `pressed` 链，`triggerKeyUp(key)` 执行 `released` 链。
- `GameViewport::keyPressEvent / keyReleaseEvent` 发出 `keyPressed / keyReleased` 信号。

### 改动

**节点定义**（`nodeDefs()`）：给全部 13 个按键节点各增加一个执行输出引脚：
- 引脚 key：`held`
- 引脚中文名：**持续按住**

**运行时**（`BPRuntime`）：
- 新增成员 `QSet<QString> m_heldKeys`。
- `triggerKeyDown(key)`：在原逻辑基础上，将 `key` 加入 `m_heldKeys`。
- `triggerKeyUp(key)`：从 `m_heldKeys` 移除 `key`。
- `triggerTick(dt)`：在执行 `Event.Tick` 链之后（或之前，顺序不敏感），遍历 `m_heldKeys`，对每个按住的键，找到对应的 `Event.Key.<key>` 节点并执行其 `held` 执行链（每帧一次，使用全新的 visited 集合）。
- 运行停止 / 重新开始时清空 `m_heldKeys`。

**自动重复过滤**（关键坑）：
- macOS 上 Qt 的按键自动重复会发出「松开 + 按下」配对事件，会把 `m_heldKeys` 中的键误删后再加回，导致 `held` 链一帧丢失。
- 处理：在 `GameViewport::keyPressEvent / keyReleaseEvent` 中，对 `e->isAutoRepeat()` 为真的事件**直接忽略**（不发 `keyPressed / keyReleased` 信号）。这样按住集合只由真实的物理按下/松开维护。

### 验收
- 按键节点显示三个引脚：按下 / 松开 / 持续按住。
- 按住 W 时，`持续按住` 链每帧触发；松开后停止。
- 长按不受系统重复延迟影响（按下后立即每帧触发，连续不顿挫）。

### 风险
中小。运行时逻辑明确；主要注意自动重复过滤，否则按住会断帧。

### 范围说明
本次以关卡蓝图运行时 `BPRuntime` 为准（地图界面用关卡蓝图）。`ActorBPRuntime` 的同等支持为可选的后续一致性工作，不在本次范围。

## 不改引擎的部分：距离 / 接近检测（纯蓝图）

判断「角色是否接近某节点」不需要算真实距离（避免开方，引擎无开方节点），只比较**距离的平方**：

```
角色位置 (x1, y1)、节点位置 (x2, y2)
dx = x1 - x2          ← 减法
dy = y1 - y2          ← 减法
平方和 = dx*dx + dy*dy  ← 乘法 ×2 + 加法
若  平方和 < 半径*半径   ← 小于   →  判定「接近」，触发
```

涉及节点全部已有：`获取位置` / `减法` / `乘法` / `加法` / `小于`。

建议在项目内用**自定义节点（Macro）** 封装为「是否接近(对象A, 对象B, 半径) → 真/假」，一次定义、到处复用。此为项目侧蓝图工作，非引擎改动。

## 验证场景（端到端）

实现两项引擎改动后，应能仅用蓝图搭出可走动的地图：

1. 地图关卡放置：角色精灵、若干敌人/交互节点精灵、主摄像机（`followTarget` = 角色）。
2. 每帧检测 WASD / 方向键「持续按住」→ 对应方向 `移动对象`。
3. 用 `数值夹取` 把角色坐标限制在地图边界内。
4. 每帧用「是否接近」自定义节点判断角色与各节点的距离。
5. 接近敌人节点 → 用全局变量记录当前节点 → `跳转关卡` 进入战斗界面。

全程无需碰撞系统。
