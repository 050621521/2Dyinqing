# 第一个小游戏 + Build in Public 内容方案 设计文档

> 日期:2026-06-18
> 目标:用 4 周(约 150 小时)做出并发布第一个游戏,同时跑通"做产品 + 做内容"的闭环。
> 背景:开发者技术强、AI 协作高效,缺现金流,选定 Build in Public 路线。这是"用一年做独立开发者"的第一颗扣子,核心目标不是做得多好,而是**真的做完并发布**。

---

## 0. 关键约束与原则

- **工时**:每天约 6 小时(晚 8 点–凌晨 2 点),4 周约 150 小时。其中开发约 120 小时,内容约 30 小时。
- **现金流兜底**:若零收入撑不过 3 个月,需另留约 30% 时间接外包急单(不计入上面 150 小时)。
- **铁律一**:范围锁死 A 档,做完了才允许加东西。
- **铁律二**:工具用 Godot,导出 HTML5 发布,绝不用自研引擎做这个游戏(自研引擎作为作品集/内容素材)。
- **铁律三**:内容是开发的副产品——开发时顺手录屏,周末集中剪 1 条,绝不让内容变成第二份工作。

---

## 1. 游戏设计

**类型**:极简牌库构筑 Roguelike(杀戮尖塔类),单人,无联机、无复杂 AI 对手(敌人用"意图"模式)。

### 1.1 核心循环

```
开始 → 第1层战斗 → 胜利三选一加卡 → 第2层 → … → 第5层 Boss → 通关/死亡 → 重开
```

一局 10–20 分钟。死亡即本局结束,重开卡组随机演化 → Roguelike 的重玩驱动力。

### 1.2 战斗系统(回合制)

- 玩家:50 生命、每回合 3 能量、初始牌组 10 张。
- 回合流程:抽 5 张 → 花能量打牌 → 结束回合(弃手牌)→ 敌人按意图行动 → 循环。
- **意图显示**(必做):敌人头顶显示下回合行为(⚔️攻击X / 🛡️防御),供玩家策略应对。
- 格挡(Block):抵挡伤害,回合结束清零。
- 死亡:生命归 0 → 本局结束。

### 1.3 内容清单(A 档,锁死)

| 类别 | 数量 | 说明 |
|---|---|---|
| 卡牌 | 15 张 | 攻击/防御/技能三类,如打击(1费6伤)、重击(2费14伤)、连刺(1费3×2)、防御(1费5格挡)、铁壁(2费12格挡)、强化(+2力量)、毒刃(伤害+中毒)、蓄能(+2能量抽1)等 |
| 敌人 | 4 种 | 史莱姆(脆)、哥布林(攻防兼备)、法师(高伤脆皮)、盗贼(上虚弱) |
| Boss | 1 个 | 多段意图 + 蓄力大招 |
| 状态效果 | 3 种 | 中毒(每回合掉血)、力量(攻击+)、虚弱(攻击-) |
| 层数 | 5 层 | 4 场普通战 + 第 5 层 Boss |

数值(50血/3能量/10初始牌等)为起始值,平衡阶段再调。

### 1.4 技术架构(核心:数据驱动)

**原则:数据驱动,绝不一卡一脚本。** 这是为将来的卡牌大作打的地基。

- 每张卡 = 一个 Godot Resource(`.tres`):名字、费用、类型、**效果数组**(如 `[造成伤害6]`、`[获得格挡5, 抽牌1]`)。
- 写一套**通用效果执行器**,解析效果数组执行。加新卡 = 填一个资源文件,不写代码。

**场景结构:**

```
Main(流程状态机:地图→战斗→奖励→…→Boss→结算)
├─ BattleScene(战斗:玩家状态 / 敌人 / 手牌区)
│   ├─ Card(卡牌节点:显示 + 拖拽出牌)
│   └─ Enemy(敌人节点:血量 + 意图)
├─ RewardScreen(三选一加卡)
└─ GameOverScreen(死亡 / 通关)
```

### 1.5 明确不做(YAGNI)

商店、事件、遗物、多角色、分支地图、多难度、存档、成就、原创美术——第一版全部不做。美术/音效用免费素材(Kenney.nl 等)+ 简单图形。

## 2. 内容方案(Build in Public)

### 2.1 定位

- 主阵地:**B站(长版开发日志)+ 抖音/视频号(切成短片)** 一鱼两吃。
- 形式:**不露脸,纯录屏 + AI 配音 + 自动字幕**。
- 核心钩子:"一个缺钱的程序员,用 AI 4 周做出并发布一个游戏" —— 用"会不会失败"制造悬念。差异化在"会写引擎的人用 AI 做游戏",不在游戏本身。

### 2.2 工具(全免费)

| 用途 | 工具 |
|---|---|
| 录屏 | OBS |
| 剪辑/字幕/AI配音 | 剪映 |
| 素材记录 | 手机备忘录(记名场面时间点) |

### 2.3 生产流水线

**每天(0 额外负担):**
1. 开发前开 OBS 录屏,结束关掉。
2. 备忘录记下三类"名场面"时间点:功能首次跑通 / 翻车 bug / AI 帮大忙或帮倒忙。

**每周(周末剪 1 条,约 2–3 小时):**
- 万能模板:前 3 秒钩子 → 中间快进开发画面 + 关键时刻/翻车 → 最后 5 秒结果 + 悬念。
- 时长 1–3 分钟竖屏;B站可发稍长完整版,抖音发切片。
- 录屏快进 4–8 倍当背景,剪映自动字幕 + AI 配音念旁白。

### 2.4 第一条视频(立 flag)

- 标题:《程序员用 AI 做游戏 Day1:4 周能做出一个杀戮尖塔吗?》
- 旁白:"我是个程序员,现在很缺钱。我决定用 4 周时间靠 AI 帮我做一个卡牌游戏然后发布它。今天第一天,我连 Godot 都没用过……但晚上让 AI 教我,居然把第一个能打的战斗做出来了。关注我,看我一个新手能不能 4 周后真的发布一个游戏。"

## 3. 4 周时间表(开发 × 内容 双线)

| 周 | 开发里程碑 | 内容线(每周末 1 条) |
|---|---|---|
| 周1 | 学 Godot 基础 + 战斗骨架:抽牌、1 攻 1 防、打赢史莱姆 | 立 flag:"4 周做尖塔" |
| 周2 | 数据驱动卡牌系统(15张)+ 3 状态效果 + 4 敌人意图 | "战斗系统成型" |
| 周3 | 流程串联(5层+三选一+Boss+结算)+ 免费美术音效 → 完整一局可通关 | "已经能玩了" + 试玩片段 |
| 周4 | 平衡 + 修 bug + 导出 HTML5 → 发布 itch.io | "上线了" + 翻车花絮 |

---

## 4. 发布

- 导出 Godot HTML5 网页版 → 上传 itch.io(免费,网页直接玩,便于视频里甩链接引流)。
- 定价:免费或"随意付费",第一个游戏目标是完成 + 引流,不指望直接收入。

---

## 5. 成功标准

1. 4 周内游戏发布到 itch.io 且可完整玩通一局。
2. 至少产出 4 条视频(每周 1 条),完成"做产品 + 做内容"闭环各一次。
3. 这套数据驱动卡牌框架可复用,为后续更大的卡牌项目打地基。

---

## 6. 风险与应对

| 风险 | 应对 |
|---|---|
| 范围膨胀,4 周做不完 | 锁死 A 档;周3 末必须有可通关的完整一局,否则砍内容保完成 |
| 通宵透支主业/健康 | 把每天 6 小时当冲刺而非常态,留意续航 |
| 零收入撑不住 | 留 30% 时间接外包急单兜底 |
| 内容拖垮开发 | 严格"顺手录 + 周末剪 1 条",不日更、不追求精剪 |
| Godot 上手卡壳 | 周1 用 AI 边学边做,优先跟现成尖塔类教程 |
