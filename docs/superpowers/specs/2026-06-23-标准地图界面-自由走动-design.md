# 标准地图界面（自由走动式）· 设计

- 日期：2026-06-23
- 状态：已确认，待实现
- 范围：MyGame「标准地图界面」关卡的最小可玩核心 + 其依赖的唯一引擎改动
- 关联：承接 `2026-06-22-自由走动地图引擎需求-design.md`（该 spec 的「持续按住」引脚、「每帧」节点已实现；摄像机跟随/边界为引擎内置）

## 背景与定位

MyGame 是一款回合制卡牌战斗游戏，当前阶段做**单人 PVE**。完整流程：

```
登录界面 → 单人模式 → 角色选择界面 → 标准地图界面 ──接触敌人──▶ 战斗地图界面
                                     （本 spec：地图导航层）        （后续阶段）
```

**标准地图界面 = 地图导航层，本身不含战斗**。玩家用 WASD / 方向键控制角色在一张大地图上自由走动（8 方向），镜头跟随；地图上有敌人节点，角色**接触即触发**战斗（跳转关卡）。

遵循项目方针：**遇到引擎不支持的功能就先开发该引擎功能**；但能用现有节点实现的就不改引擎。

## 已定设计决策

| 维度 | 决策 |
|---|---|
| 地图形态 | 自由走动的 2D 地图（非固定节点图） |
| 地图尺寸/镜头 | 大地图 + 镜头跟随 |
| 交互节点 | 第一版**只有敌人节点** |
| 敌人行为 | **静止**（不巡逻/不追击） |
| 触发方式 | **接触即触发**（进入接触半径自动跳转战斗） |
| 打赢之后 | 敌人消失（状态保存逻辑留后续） |
| 操作键 | WASD + 方向键都支持 |
| 移动 | 8 方向，配套 8 方向行走动画 |
| 地图边界 | 开阔地 + 边界墙（无内部障碍物） |
| 敌人数量/摆放 | **2 个，运行时随机摆放** |
| 接触检测 | 自定义节点（Macro）「是否接近」，距离平方比较，**不改引擎** |

## 能力盘点（对照引擎现状）

### ✅ 引擎已具备 / 已实现（无需开发）

| 能力 | 实现方式 |
|---|---|
| 镜头跟随 | 引擎内置**「跟随控制组件」**：摄像机配 `followTarget` 平滑插值跟随 + 偏移（`BPRuntime.cpp` Pass 1） |
| 摄像机边界 | 引擎内置 `confiner` 边界夹取 |

| 移动 / 取位置 | `设置自身位置` / `获取自身位置` / `移动对象` / `获取位置` |

### 🔧 需要开发的引擎改动（仅一项）

**随机数节点** —— 引擎当前无任何随机来源，随机摆放敌人必须依赖它。

## 引擎改动：随机数节点

- **typeId**：`Math.Random`
- **中文显示名**：**随机数**
- **header 颜色**：数学类配色（与 `Math.Add` 等一致）
- **引脚**：
  - `min`（数据输入，中文「最小值」）
  - `max`（数据输入，中文「最大值」）
  - `result`（数据输出，中文「结果」，数值类型）
- **产出**：`[最小值, 最大值]` 区间内的**随机小数**（需要整数时由调用方接 `数值夹取` / 取整处理）。

### 实现位置

1. `launcher/src/editor/BlueprintEditor.cpp` `nodeDefs()`：注册 `Math.Random` 节点定义。
2. `launcher/src/editor/BPRuntime.cpp` 数据求值（`Math.Add` 等所在的 `evalDataPin` 同一处，约 564 行附近）：新增
   ```cpp
   if (node->type == "Math.Random" && pinKey == "result") {
       const double mn = resolveDataPin(nodeId, "min").toNumber();
       const double mx = resolveDataPin(nodeId, "max").toNumber();
       const double lo = std::min(mn, mx), hi = std::max(mn, mx);
       return BPValue::fromNumber(lo + QRandomGenerator::global()->generateDouble() * (hi - lo));
   }
   ```
3. `launcher/src/editor/ActorBPRuntime.cpp`：同等求值分支（保持关卡蓝图与 Actor 蓝图一致）。

### 求值语义说明

纯数据节点，每次读取 `result` 都重新取随机值。摆放敌人时一次性读取写入坐标，符合预期；调用方应避免在同一逻辑里对同一随机节点的输出做多次「应当相等」的读取。

### 验收

- 右键菜单可添加「随机数」节点，含 最小值 / 最大值 / 结果 三引脚。
- 关卡蓝图与 Actor 蓝图运行时都能求出区间内随机数。
- 把敌人坐标设为随机数节点输出，每次运行敌人位置不同。

### 风险

低。与现有 Math 节点同构，仅多一处求值分支 + 一个节点定义。

## 项目内容：自定义节点「是否接近」（Macro，不改引擎）

判断角色是否接触敌人，用**距离平方比较**（引擎无开方节点，比较平方避免开方）：

```
对象A 位置 (x1,y1)、对象B 位置 (x2,y2)、半径 r
dx = x1 - x2 ;  dy = y1 - y2
平方和 = dx*dx + dy*dy
是否接近 = 平方和 < r*r
```

- 封装为自定义节点（`.bpmacro`）：**是否接近(对象A, 对象B, 半径) → 布尔**。
- 用到的节点全部已有：`获取位置` / `减法` / `乘法` / `加法` / `小于`。
- 一次定义、到处复用（后续多敌人 / 战斗判定都能用）。

## 项目内容：角色蓝图（`Blueprints/角色.bp` 的 Self 逻辑）

- **每帧 + 持续按住**：读取当前按住的方向键 → 合成 8 方向移动向量 → `设置自身位置`（速度 × 帧间隔）。
- **边界**：移动后用 `数值夹取` 把自身 x / y 限制在地图范围内。
- **动画**：按移动方向播放对应行走 clip；无键按下时停在站立帧。
- 修正现有隐患：`角色.bp` 的 `animAsset` 当前写死武夫、未按全局变量 `角色` 切换 —— 接入按 `角色` 选 `武夫.anim` / `机械师.anim`（若机械师动画缺失则先都用武夫，标注 TODO）。

## 项目内容：标准地图界面关卡蓝图（导演逻辑）

- **开始运行**：用**随机数节点**把 2 个预先摆放的敌人 Actor 移到地图范围内随机坐标。避免叠在角色出生点附近的做法：**直接划定一块不含出生点的子区域**（如出生点在地图下方，则敌人只在地图上半区取随机），无需循环重摇（蓝图无通用 while 循环）。
- **每帧**：
  1. （镜头跟随由内置组件处理，无需蓝图）
  2. 用「是否接近」自定义节点判断角色与 2 个敌人各自的接触；任一为真 → `跳转关卡` 进入战斗地图界面。

## 关卡摆放

- 角色精灵（`角色.bp` 实例），出生点固定。
- 2 个敌人精灵 Actor（预先摆放，运行时被随机重定位）。
- 主摄像机：配「跟随控制组件」`跟随目标 = 角色`；`confiner` 设为地图边界。
- 地图背景图（占位，后续替换）。

## 待调参数（先给默认值，编辑器内调）

地图尺寸、角色移动速度、接触半径、敌人随机范围与最小间距、地图背景图。

## 不做（明确排除，留后续阶段）

- 战斗地图界面本身（卡牌战斗）。
- 通关 / 结算逻辑、跨界面状态保存（敌人消失记录、角色坐标恢复）。
- 敌人节点以外的交互节点（商店 / 事件 / 休息 / 宝箱）。
- 敌人移动 AI（巡逻 / 追击）。
- 地图内部障碍物与碰撞系统。
- 接触检测的原生引擎节点（用 Macro 替代）。
