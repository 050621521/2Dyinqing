# 封装层：宏式自定义节点（折叠 / 宏库）设计文档

日期：2026-06-15
状态：方向已确认（照虚幻两层模型），待评审

## 背景与动机

用户需要把一段蓝图逻辑**打包成一个可复用的自定义节点**，反复调用。典型验收目标：用户不写一行 C++，纯靠"框选 → 折叠"，造出一个有**多个执行出口**的「多条件分支控制」节点。

这正是虚幻的**宏（Macro）**能力。本设计照搬虚幻结构，落地到本项目的解释执行蓝图系统。

> 前置依赖：本设计复用引擎层「[动态引脚框架]」（见 `2026-06-15-blueprint-switch-dynamic-pins-design.md`）。自定义节点实例的引脚同样按"实例引用的资产"动态计算，不写死。**实现顺序：先引擎层单值分支（含动态引脚地基），后本封装层。**

## 目标与范围

**本子项目做：**
1. **宏式自定义节点**：内部是一段子图，可有**多个执行输入/输出口**，运行时**内联展开**、共享调用方 `self` 上下文。
2. **入口/出口边界节点**：在节点内部用两个特殊节点声明对外引脚。
3. **折叠交互**：框选 → 自动按穿越边界的连线推引脚 → 替换为一个调用节点。
4. **两层模型（照虚幻）**：本地折叠（存当前蓝图、仅本图可见） / 提升为库（独立 `.bpmacro` 资产、全工程可见）。
5. **编辑与复用**：双击进内部编辑；接口变则所有实例同步重算引脚；右键菜单"自定义节点"分类列出宏库资产。
6. **运行时**：递归解释，入口/出口做引脚映射；禁止循环引用。
7. **前置补缺**：框选/多选能力（当前编辑器只支持单选）。

**本子项目不做（后续）：**
- 函数式封装（独立作用域、单返回、局部变量）。
- 宏的版本管理 / 重命名批量重构。
- 跨工程的宏共享。

## 前置补缺：框选 / 多选

当前 `BlueprintEditor` 只有单选（`m_selectedNodeId`）。折叠的前提是能一次选中多个节点：

- 新增 `QSet<QString> m_selectedNodeIds`（保留 `m_selectedNodeId` 作"主选中/细节展示"兼容，或统一迁移）。
- 空白处按下拖拽 → 橡皮筋框选（marquee），框内节点全部选中。
- `Shift/Cmd + 点击` 增减选中。
- 绘制：选中节点统一高亮描边。

> 这是独立、可先行的一步，也让后续"批量删除/移动"受益。

## 核心模型：宏 = 内联子图

- **内联语义**：调用节点被触发时，等价于把宏内部子图"展开"到调用处；子图里的 `self` 就是调用方的 `self`，不另开作用域。
- **多执行口**：宏可有多个 exec 输入、多个 exec 输出——这是"多路分支"能被封装的根本。
- **数据口**：宏可有数据输入/输出引脚。

## 数据模型

### 宏库资产 `BPMacro`（可复用层）

新增结构，存独立文件 `{project}/Blueprints/Macros/*.bpmacro`（JSON）：

| 字段 | 含义 |
|---|---|
| `id` | 稳定唯一 id（调用节点按它引用，重命名不丢连接） |
| `name` | 显示名（如"多条件分支控制"） |
| `filePath` | 存盘路径 |
| `inputPins` | 对外**输入**引脚列表：`{key, label, isExec, kind}` |
| `outputPins` | 对外**输出**引脚列表 |
| `nodes` / `connections` | 内部子图，复用现有 `BPNode` / `BPConnection` 序列化 |

`inputPins`/`outputPins` 的 `key` 用**稳定 id**（如 `in_<uuid>` / `out_<uuid>`），增删引脚不影响其它引脚 key，已连线不错位。

### 本地折叠节点（仅本图层）

本地折叠不产出独立资产，子图**内联存在宿主文档里**：调用节点 `type = "Macro::local"`，`params["subgraph"]` 存该子图的 JSON（含 inputPins/outputPins/nodes/connections，同 `BPMacro` 的结构）。仅这张蓝图引用、可见。

### 调用节点

调用节点是宿主图里一个普通 `BPNode`：
- 引用库资产：`type = "Macro::<macroId>"`。
- 本地折叠：`type = "Macro::local"`，子图存自身 `params`。

调用节点的引脚**不写死**——`effectivePins` 发现 `type` 以 `Macro::` 开头，就去取对应宏（库资产或本地子图）的 `inputPins`（作输入）+ `outputPins`（作输出）来算。**这是复用引擎层动态引脚地基的接入点。**

## 入口 / 出口边界节点

宏内部子图固定含两个特殊节点：

| 节点 | 引脚方向 | 含义 |
|---|---|---|
| **入口节点**（`Macro.Entry`） | 它的**输出**引脚 = 宏的 `inputPins` | 在子图里拿外部传入的执行流/数据 |
| **出口节点**（`Macro.Exit`） | 它的**输入**引脚 = 宏的 `outputPins` | 往里接，决定走哪个对外出口 |

这两个节点本身也吃动态引脚框架（引脚来自宏的接口定义）。在入口/出口上加一个引脚 = 给这个自定义节点加一个对外的口。多路分支的"多个出口"就是在出口节点上加多个 exec 输入引脚。

## 折叠交互

### 自动推引脚规则

框选若干节点 → 右键「折叠节点」→ 看连线与选区边界的关系：

| 连线情况 | 结果 |
|---|---|
| 外部 → 选区内某引脚（穿入） | 生成一个**输入**引脚（exec 入线→exec 输入；数据线→数据输入），写入入口节点 |
| 选区内某引脚 → 外部（穿出） | 生成一个**输出**引脚，写入出口节点 |
| 两端都在选区内 | 留在子图内部，不暴露 |
| 多根外部线接到同一个内部引脚 | 合成**一个**边界引脚 |

引脚 `kind` 沿用源引脚类型（复用引脚类型系统）。引脚 label 取内部目标引脚名作默认，可后续改名。

### 折叠后

- 选中节点整体搬进子图（本地：存 `params["subgraph"]`）。
- 宿主图在选区重心放一个调用节点，原穿越边界的外部线改接到调用节点对应新引脚。
- 弹命名框。
- 默认产出**本地折叠节点**（照虚幻"折叠节点"默认本地、不污染全局菜单）。

### 提升为库

本地折叠节点上右键「**提升为宏库资产**」：
- 子图序列化为 `{project}/Blueprints/Macros/<name>.bpmacro`，分配稳定 `id`。
- 该调用节点改为 `type = "Macro::<id>"`（引用资产）。
- 此后所有蓝图右键"自定义节点"菜单出现它。

## 编辑与复用

- **双击**调用节点 → 打开其子图编辑（新开编辑页/标签，复用 `BlueprintEditor`，同现蓝图 tab 套路）。本地折叠编辑自身 `params`；库资产编辑 `.bpmacro` 文件。
- 内部可照常增删节点/连线，并在入口/出口节点上增删引脚。
- **接口变 → 实例同步**：库资产的 `inputPins`/`outputPins` 变化后，所有引用它的调用节点引脚重算（key 稳定，连线保留；被删引脚上的连线按规则清理）。
- 右键空白菜单新增「**自定义节点**」分类，列出当前工程 `Macros/` 下所有宏资产。

## 运行时（BPRuntime · 递归解释）

调用节点执行时**压一个"宏调用帧"**，记住是哪个调用节点触发、引用哪个宏，然后进子图：

- **执行流入**：调用节点被触发的 exec 输入 → 映射到入口节点对应的 exec 输出 → 子图往下跑。
- **执行流出**：子图跑到出口节点某个 exec 输入 → 弹帧回宿主 → 顺着调用节点**对应的那个 exec 输出**继续。多路分支由此实现。
- **数据流**：
  - 子图里读"入口节点的数据输出" → 翻译为读宿主中调用节点对应数据输入。
  - 宿主读"调用节点的数据输出" → 翻译为读子图中出口节点对应数据输入。
- **上下文**：内联语义，子图 `self` = 宿主 `self`，不另开作用域。
- **嵌套**：宏里可放别的宏，靠帧栈支持。

**防死循环**：编辑时禁止把一个宏直接或间接放进它自己（引用成环检测）；运行时帧栈另设深度上限兜底。

## 验证

1. **框选**：橡皮筋框选多个节点，高亮正确；Shift/Cmd 增减选。
2. **折叠**：框选一段逻辑 → 右键折叠 → 自动推出正确的输入/输出引脚，外部线接上，选区变一个本地节点。
3. **多出口**：折叠一段有多个对外执行分支的逻辑，调用节点出现多个 exec 输出口。
4. **提升为库**：本地折叠 → 提升 → `Macros/` 下生成 `.bpmacro`，其它蓝图右键菜单可见并可放置。
5. **编辑同步**：双击进库宏，增删一个出口引脚 → 所有实例同步多/少一个口，无关连线不错位。
6. **运行**：调用节点按内部逻辑只走命中的那个出口；数据进出映射正确；`self` 为调用方。
7. **嵌套与防环**：宏里放宏可正常跑；试图把宏放进自身被阻止。
8. **端到端验收**：纯靠折叠 + 提升，造出可复用的「多条件分支控制」并在另一关卡使用、运行正确。
9. 保存/重开关卡与工程，本地折叠子图、库引用、连线均正确还原。
